# Расширение для браузера (спецификация)

Статус: **первая версия для Chrome и Edge** (шаги 1–5 и всплывающее окно из шага 6 [порядка реализации](#implementation-order)). Документ описывает, как расширение Erapkey для браузера общается с настольным приложением, что оно может запрашивать и как устанавливаются части системы. Код каналов (pipe), общий с SSH-агентом, описан в [ssh-agent.md](ssh-agent.md).

Код: `Erapkey.Core/Services/Browser/` (протокол, сопряжение, криптография сеанса), `Erapkey.Core/Services/WebsiteMatcher.cs` и `PublicSuffixList.cs`, `Erapkey.NativeHost/`, `Erapkey.Desktop/Services/BrowserBackend.cs` и `NativeMessagingRegistration.cs`, `extension/`. Тесты: `Erapkey.Core.Tests/BrowserPipeServerTests.cs`, `WebsiteMatcherTests.cs` и `BrowserExtensionInteropTests.cs`, который запускает TypeScript-код протокола расширения в Node против C#-сервера.

## Цели

- Предлагать и подставлять логины в Chrome, Edge и Firefox (и других браузерах на основе Chromium) из хранилища (vault) запущенного Erapkey.
- Подбирать записи по адресу, который браузер сообщает для вкладки, чтобы сайт-двойник не получал подсказок. Всплывающее окно быстрого доступа больше не читает адресную строку браузера (UI Automation не мог определить схему, нужное поле ввода и отличить вводимый текст от адреса страницы); оно выключено по умолчанию и остаётся для других приложений.
- Хранилище никогда не покидает настольное приложение. Расширение получает одну запись за раз, после действия пользователя, и не хранит секреты в хранилище браузера.

Не входит в первую версию: сохранение новых логинов из браузера, passkeys, карты и удостоверения личности, подстановка без запущенного Erapkey.

## Архитектура

```
Extension (Manifest V3)
  background service worker ── chrome.runtime.connectNative("com.erapkey.host")
        │  Native Messaging: stdin/stdout, JSON
        ▼
Erapkey.NativeHost.exe        started by the browser, one per extension connection
        │  \\.\pipe\erapkey-browser-<user SID>, length-prefixed JSON
        ▼
Erapkey.exe                   BrowserPipeServer → unlocked vault, pairing and unlock windows
```

Браузеры не умеют открывать именованные каналы или локальные сокеты; Native Messaging — поддерживаемый способ для расширения обратиться к локальной программе. Браузер запускает программу из зарегистрированного манифеста и только для перечисленных там идентификаторов расширений.

Локальный HTTP- или WebSocket-сервер **не** используется: любая веб-страница может отправлять запросы на `localhost`, что потребовало бы собственной аутентификации и защиты от DNS rebinding.

### Компоненты

| Компонент | Расположение | Роль |
|---|---|---|
| Расширение | `extension/` (новое) | Обнаруживает формы входа, показывает подсказки, заполняет поля, хранит ключ сопряжения. TypeScript, сборка esbuild. |
| Native host | `Erapkey.NativeHost/` (новый проект) | Передаёт сообщения между браузером и каналом. Не имеет доступа к хранилищу и не содержит логики. |
| Сервер для браузера | `Erapkey.Desktop` + `Erapkey.Core` | Сервер канала, сопряжение, криптография сеанса, сопоставление URL, ответы. |

Native host — отдельный исполняемый файл, а не `Erapkey.exe` с флагом: браузер запускает путь из манифеста **без выбранных нами аргументов** (Chrome передаёт origin расширения, Firefox — путь к манифесту и ID расширения), а host не должен выполнять хуки Velopack, занимать мьютекс единственного экземпляра или загружать WPF. Это небольшое консольное приложение, опубликованное с Native AOT, поэтому оно быстро запускается и не требует среды выполнения.

### Отдельный канал, не канал SSH-агента

Сервер для браузера использует собственный канал, а не канал SSH-агента: протоколы различаются (JSON против бинарного протокола SSH-агента), различается доверие (агент никогда не выдаёт ключи, а сервер для браузера возвращает пароли), и каждый можно отключить отдельно. Настройка канала общая: код, общий для `SshAgentServer` и `BrowserPipeServer` (ACL, `FirstPipeInstance`, цепочка процессов клиента, цикл приёма подключений), выносится в базовый класс `NamedPipeServer` в `Erapkey.Core`.

## Регистрация native host

Манифест записывается в `%LOCALAPPDATA%\Erapkey\browser\com.erapkey.host.<browser>.json` и регистрируется для текущего пользователя (права администратора не нужны):

| Браузер | Ключ реестра (значение по умолчанию = путь к манифесту) |
|---|---|
| Chrome и браузеры на Chromium, читающие ключ Chrome (Brave, Vivaldi) | `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.erapkey.host` |
| Edge | `HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.erapkey.host` |
| Firefox | `HKCU\Software\Mozilla\NativeMessagingHosts\com.erapkey.host` |

Манифест для Chromium:

```json
{
  "name": "com.erapkey.host",
  "description": "Erapkey",
  "path": "C:\\Users\\<user>\\AppData\\Local\\Erapkey.App\\current\\Erapkey.NativeHost.exe",
  "type": "stdio",
  "allowed_origins": ["chrome-extension://<Chrome Web Store ID>/", "chrome-extension://<Edge Add-ons ID>/"]
}
```

Firefox вместо `allowed_origins` использует `"allowed_extensions": ["erapkey@<domain>"]`.

- Установленная сборка регистрируется в хуках установки и обновления Velopack (`Program.Main` → `VelopackApp`) и снимает регистрацию при удалении. `current\` — стабильная папка Velopack, поэтому обновления не меняют путь.
- Портативная сборка проверяет регистрацию при каждом запуске и перезаписывает её, если путь изменился.
- **Настройки → Безопасность → Расширение для браузера** (Settings → Security → Browser extension) отключает интеграцию: снимает регистрацию host и останавливает сервер канала.
- Отладочные (Debug) сборки регистрируют собственное имя host; см. [Разработка](#development).

## Транспорт

### Браузер ↔ native host

Фрейминг Native Messaging: 32-битная длина в собственном порядке байт (little-endian в Windows), затем JSON в UTF-8. Сообщение от host к браузеру — не более 1 МБ. Когда расширение отключается, браузер закрывает stdin, и host завершается.

<a id="native-host--erapkey"></a>
### Native host ↔ Erapkey

`\\.\pipe\erapkey-browser-<user SID>`, та же защита канала, что и у SSH-агента: ACL только для текущего пользователя, сетевые входы запрещены, `FirstPipeInstance`. Фрейминг: 32-битная длина в big-endian, затем JSON в UTF-8, не более 1 МБ.

Host подключается к каналу один раз, когда его запускает браузер, и пересылает каждое сообщение без изменений в обе стороны. Он не может добавить `id` к собственным ответам (после `hello` сообщения зашифрованы), поэтому о проблемах сообщает событиями:

- Канала не существует (Erapkey не запущен или интеграция отключена): host пишет `{ "event": "app_not_running" }` и завершается.
- Erapkey закрывает канал (выход, интеграция отключена): host завершается; браузер сообщает, что порт отключён.

Расширение не переподключается в цикле: оно подключается снова (новый процесс host и новый `hello`) при следующем действии пользователя, например при открытии всплывающего окна на панели инструментов или фокусе на поле входа.

### Проверка клиента

Для каждого подключения к каналу сервер получает цепочку процессов клиента (как и SSH-агент, см. [ssh-agent.md](ssh-agent.md#confirmation)):

- клиент должен быть `Erapkey.NativeHost.exe` из папки приложения, иначе подключение закрывается и записывается в журнал;
- браузер — первый процесс выше него, не являющийся `cmd.exe` (Chrome и Edge запускают native host через `cmd /d /s /c`). Он показывается в окне сопряжения (`chrome.exe`, `msedge.exe`, …) и сохраняется вместе с сопряжением, но не проверяется принудительно: браузеров на основе Chromium много.

Эта проверка лишь не даёт другим программам случайно обращаться к каналу: любая программа пользователя может сама запустить `Erapkey.NativeHost.exe`. Ответы защищает ключ сопряжения, описанный ниже.

## Сопряжение (pairing)

ACL канала позволяет подключиться любому процессу пользователя, поэтому сервер дополнительно требует ключ, которым владеет только сопряжённое расширение.

Ключи — ECDH на P-256: его поддерживают и WebCrypto во всех поддерживаемых браузерах, и `ECDiffieHellman` в .NET.

1. При установке расширение генерирует статическую пару ключей и хранит её в IndexedDB как неизвлекаемый `CryptoKey`. `chrome.storage` не подходит: он хранит только JSON, и закрытый ключ пришлось бы экспортировать.
2. `associate` отправляет статический открытый ключ расширения и имя (`Chrome`, `Edge`, …). Erapkey генерирует собственную статическую пару ключей для этого сопряжения.
3. Обе стороны показывают шестизначный код: первые 4 байта `SHA-256("erapkey-pair" || appPublic || extensionPublic)` как число в big-endian по модулю 1 000 000, дополненное нулями. Erapkey показывает окно: *Подключить браузер «Chrome» (chrome.exe)? Код 482 917*; всплывающее окно расширения показывает тот же код.
4. Пользователь подтверждает в Erapkey. Сопряжение сохраняется, а расширение получает идентификатор сопряжения и статический открытый ключ приложения.

Сопряжения привязаны к устройству и не синхронизируются. Они хранятся в `%LOCALAPPDATA%\Erapkey\browserPairings.dat`, защищённые DPAPI для текущего пользователя (как облачные токены, см. `ProtectedTokenHolder`):

```jsonc
{ "Id": "<guid>", "Name": "Chrome", "Browser": "chrome.exe",
  "ExtensionPublicKey": "<base64 SPKI>", "AppPrivateKey": "<base64 PKCS#8>",
  "CreatedAt": "<UTC>", "LastUsedAt": "<UTC>" }
```

**Настройки → Безопасность → Расширение для браузера** показывает сопряжения с временем последнего использования и позволяет их удалить. После удаления сопряжения расширение снова запросит сопряжение.

Сопряжение работает при заблокированном хранилище: оно ничего не раскрывает о хранилище.

## Сеанс

Каждое подключение начинается с `hello`, который аутентифицирует обе стороны и создаёт ключи сеанса:

1. Расширение → `hello { pairingId, ephemeralKey, nonce }` (простым JSON).
2. Erapkey → `hello { ephemeralKey, nonce }` или ошибка `not_paired`.
3. Обе стороны вычисляют
   `secret = ECDH(appStatic, extensionStatic) || ECDH(appEphemeral, extensionEphemeral)`
   `keys = HKDF-SHA256(secret, salt = nonceExt || nonceApp, info = "erapkey-browser-v1")` → 32 байта расширение→приложение, 32 байта приложение→расширение.
4. Каждое последующее сообщение имеет вид `{ "n": <counter>, "c": "<base64 AES-256-GCM ciphertext>" }`. Nonce — 64-битный счётчик своего направления, дополненный до 12 байт; счётчик должен расти ровно на единицу, иначе сеанс закрывается.

Без статического закрытого ключа сопряжённого расширения процесс не может вывести ключи сеанса и ничего не получит. Статический ключ лежит в профиле браузера; программа, запущенная от того же пользователя, может его прочитать — так же, как может прочитать память разблокированного Erapkey. Сопряжение защищает от других программ, которые просто подключаются к каналу, но не от вредоносного ПО, уже владеющего учётной записью пользователя.

## Запросы

Внутри сеанса запросы и ответы — это JSON-объекты с `id`, выбираемым расширением:

```jsonc
// request
{ "id": 7, "type": "getLogins", "url": "https://login.example.com/signin" }
// response
{ "id": 7, "ok": true, "logins": [ ... ] }
// error
{ "id": 7, "ok": false, "error": "locked" }
```

| Запрос | Ответ | Примечания |
|---|---|---|
| `status` | `{ locked, version }` | |
| `unlock` | `{ locked }` | Показывает окно разблокировки (как запрос SSH-агента) и отвечает, когда хранилище разблокировано, или с `locked: true` через минуту. |
| `getLogins { url }` | `logins: [{ entryId, name, login, match }]` | Логины, сайт которых соответствует `url` (см. ниже), лучшее совпадение первым. `match` — `exact` или `domain`. **Без паролей.** |
| `getCredentials { entryId, url }` | `{ login, password, totp? }` | Только если запись всё ещё соответствует `url`; иначе `not_found`. `totp` — текущий код, если у записи есть TOTP. |
| `openEntry { entryId }` | `{}` | Выводит Erapkey на передний план с выбранной записью. |

События, которые Erapkey отправляет без запроса: `{ "event": "locked" }`, `{ "event": "unlocked" }`, `{ "event": "vaultChanged" }` (определено, но пока не отправляется: всплывающее окно запрашивает данные заново при каждом открытии). При `locked` расширение сбрасывает всё, что показывало. Native host отправляет `{ "event": "app_not_running" }` простым JSON (см. [Транспорт](#native-host--erapkey)).

Ошибки: `locked`, `not_paired`, `not_found`, `bad_request`, `unsupported_version`, `internal`.

Правила:

- Нет запроса, который перечисляет хранилище или возвращает записи без URL. Даже скомпрометированное расширение получит только логины тех сайтов, которые посещает пользователь.
- `getCredentials` повторяет проверку URL: одного идентификатора записи недостаточно.
- Окна подтверждения на каждую подстановку нет: щелчок в браузере — согласие пользователя. Позже настройка может добавить его.
- `version` в `hello` и `status` — версия протокола (`1`). Более новое расширение со старым Erapkey получает `unsupported_version` и просит пользователя обновиться.

## Сопоставление URL

`Erapkey.Core/Services/WebsiteMatcher.cs` (новый). Сайт записи берётся из `Login.SiteField` и разбирается так же, как сейчас это делает `LoginViewModel.ParseWebsite` (отсутствие схемы означает `https`).

1. Нормализовать оба хоста: нижний регистр, IDN в punycode, без завершающей точки.
2. **Exact** (точное): тот же хост (и тот же порт, если он есть у записи).
3. **Domain** (по домену): тот же регистрируемый домен по [Public Suffix List](https://publicsuffix.org/) (eTLD+1): `login.example.com` соответствует записи для `example.com`, но `example.co.uk` не соответствует `other.co.uk`, а `alice.github.io` не соответствует `bob.github.io`. Список находится в `Erapkey.Core/Resources/public_suffix_list.dat`, встроенном ресурсе, который читает `PublicSuffixList` (обычные правила, правила с подстановкой `*.` и исключения `!`, секции ICANN и private одинаково); для хоста, не покрытого ни одним правилом, действует неявное правило `*` (суффикс — его последняя метка). Файл обновляется вместе с релизами.
4. IP-адреса и хосты из одной метки (`localhost`, `router`) соответствуют только точно.
5. Запись, сохранённая с `https`, не предлагается на странице `http` (понижение защиты). Запись `http` предлагается на `https`.
6. Только страницы `http` и `https`; никогда `file:`, `chrome:`, `about:` или страницы расширений.

## Расширение

Manifest V3, TypeScript, сборка esbuild (`extension/`, `npm run build` → `extension/dist/`). Первая версия ориентирована на Chrome и Edge, у которых общий манифест. Firefox появится позже со своим манифестом: он запускает фоновый код MV3 как `background.scripts` (событийная страница), а не как service worker, и требует `browser_specific_settings.gecko.id`.

- **Фоновый service worker**: нативный порт, сопряжение, криптография сеанса, очередь запросов. Открытый порт native messaging поддерживает service worker живым в современных браузерах; когда worker или порт исчезают, он подключается снова (новый `hello`) при следующем действии пользователя.
- **Всплывающее окно на панели инструментов**: состояние (не запущен / заблокирован / разблокирован), кнопка разблокировки, логины для текущей вкладки, код сопряжения во время сопряжения. Выбор логина подставляет его во вкладку (`chrome.scripting.executeScript` с `activeTab`, `src/fill.ts`). Копирования в буфер обмена нет: пароль попал бы в журнал Win+V, а при включённой синхронизации буфера — в облако Microsoft. При подстановке проверяется, что вкладка всё ещё находится на origin адреса, по которому подобран логин.
- **Content script** (пока нет): находит формы входа (поля пароля, поля имени пользователя перед ними, в том числе в iframe того же origin), показывает встроенный значок Erapkey в поле, подставляет по выбору пользователя.

Правила подстановки:

- Подставлять только после действия пользователя: выбора логина во встроенном меню или всплывающем окне либо сочетания клавиш. Никогда при загрузке страницы, чтобы скрытые формы не могли собирать пароли.
- Подставлять только в видимые, доступные поля страницы верхнего уровня или фреймов того же origin. Фрейм другого origin сопоставляется по собственному URL, а не по URL страницы.
- Вызывать события `input` и `change`, чтобы скрипты страницы заметили значения.
- В поле одноразового кода логин не подставляется никогда. Такое поле узнаётся по `autocomplete="one-time-code"`; по словам в имени, id, placeholder или подписи (`otp`, `2fa`, `mfa`, `passcode`, `one time`, `verification code` и подобным, но не почтовый индекс, промокод или код карты); по короткому полю только для цифр (`inputmode="numeric"`, 4–8 символов); или по четырём и более полям по одному символу. В него подставляется текущий TOTP-код записи (`totp` из `getCredentials`), по цифре в каждое поле, если код разбит. Если страница просит только код, а у записи нет TOTP, всплывающее окно об этом сообщает (`no_totp`).
- Пароли остаются в памяти только на время подстановки; ничего из хранилища не попадает в `chrome.storage`.

## Настройки в Erapkey

**Настройки → Безопасность → Расширение для браузера**:

- *Интеграция с браузером* вкл./выкл. — регистрирует или снимает регистрацию native host и запускает или останавливает сервер канала. По умолчанию выключена, пока расширение не опубликовано.
- Сопряжённые браузеры: имя, браузер, последнее использование, **Удалить**.

## Разработка

Отладочные сборки Erapkey — отдельный экземпляр, поэтому тестирование расширения никогда не затрагивает рабочее хранилище и может идти рядом с установленным приложением:

| | Release | Debug |
|---|---|---|
| Папка данных (хранилище, настройки, журналы, сопряжения) | `%LOCALAPPDATA%\Erapkey` | `%LOCALAPPDATA%\Erapkey.Dev` |
| Каналы | `erapkey-ssh-agent-<SID>`, `erapkey-browser-<SID>` | то же с `-dev` |
| Мьютекс единственного экземпляра, межпроцессное окно | как сейчас | с `-dev` |
| Имя native host | `com.erapkey.host` | `com.erapkey.host.dev` |

`Constants.IsDevBuild` (символ `DEBUG` в `Erapkey.Core`) переключает все эти значения. Сборка Debug регистрирует `com.erapkey.host.dev` для `Erapkey.NativeHost.exe`, лежащего рядом в `bin\Debug`, с ID распакованного расширения в `allowed_origins`. Расширение для разработки (`npm run build:dev`) подключается к `com.erapkey.host.dev`; в его манифесте задан фиксированный `key`, поэтому Chrome и Edge присваивают распакованному расширению один и тот же ID на любой машине.

Чтобы попробовать: соберите решение в Debug, запустите Erapkey (он создаст новое пустое хранилище в `Erapkey.Dev`), включите **Настройки → Безопасность → Расширение для браузера**, выполните `npm install` и `npm run build:dev` в `extension/`, откройте `chrome://extensions` (или `edge://extensions`), включите режим разработчика и загрузите `extension/dist/`.

Для установленного Erapkey выполните `npm run build:unpacked` в `extension/` и загрузите ту же папку. Эта сборка подключается к `com.erapkey.host` и содержит ключ для ID `mhnlllocpadmflggkijecmklkooflbbe`. Если папка уже загружена с другим ID, удалите прежнюю запись расширения и загрузите папку заново.

<a id="implementation-order"></a>
## Порядок реализации

1. Разделение отладочного экземпляра (выше).
2. `Erapkey.Core`: `PublicSuffixList` и `WebsiteMatcher` с тестами.
3. Базовый `NamedPipeServer`, выделенный из `SshAgentServer`; `BrowserPipeServer` с протоколом, сопряжением и криптографией сеанса, с тестами (тестовый клиент изображает расширение).
4. `Erapkey.NativeHost` (Native AOT), регистрация в хуках Velopack, для портативной сборки и для Debug, упаковка.
5. Окно сопряжения и **Настройки → Безопасность → Расширение для браузера** в `Erapkey.Desktop`.
6. Расширение для Chrome и Edge: сначала фоновый worker и всплывающее окно (список и копирование), затем content script и встроенная подстановка.
7. Firefox: его манифест и регистрация.
8. Страницы в магазинах (Chrome Web Store, Edge Add-ons, Firefox AMO); их ID расширений попадают в манифесты.
