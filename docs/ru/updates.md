# Обновления приложения

SinglePass обновляется сам из [GitHub Releases](https://github.com/Erapchu/SinglePass.WPF/releases) с помощью [Velopack](https://velopack.io). В этом документе описано, как собираются релизы, как приложение находит и устанавливает их и куда попадают файлы.

Код:

- `SinglePass.WPF/Program.cs` — точка входа; запускает хуки Velopack до старта WPF.
- `SinglePass.WPF/Services/UpdateService.cs` — проверяет, скачивает и применяет обновления.
- `SinglePass.WPF/App.xaml.cs` — запускает службу обновлений после разблокировки и предлагает перезапуск.
- `SinglePass.WPF/Views/Controls/AboutControl.xaml` — карточка **Settings → About → Updates**.
- `.github/workflows/dotnet-desktop.yml` — собирает, упаковывает и публикует релиз.

## Содержимое релиза

Каждый релиз содержит:

| Файл | Назначение |
|---|---|
| `SinglePass.WPF-win-Setup.exe` | Установщик для новых пользователей. |
| `SinglePass.WPF-win-Portable.zip` | Портативная копия, которая тоже обновляется сама. |
| `SinglePass.WPF-X.Y.Z-full.nupkg` | Полный пакет приложения. Скачивается, когда дельта неприменима. |
| `SinglePass.WPF-X.Y.Z-delta.nupkg` | Разница с предыдущим релизом. Отсутствует в первом релизе на Velopack. |
| `releases.win.json` | Лента обновлений: версии, имена файлов, размеры и хеши SHA256. |

Само приложение публикуется как автономная (self-contained), однофайловая сборка ReadyToRun для Windows x64.

## Установка

### Setup.exe

Setup.exe устанавливает приложение для текущего пользователя без прав администратора и без мастера, затем запускает приложение.

```
%LocalAppData%\SinglePass.WPF\
  Update.exe              Velopack updater
  current\                application files; replaced on update
  packages\               downloaded packages
```

Также создаются ярлыки в меню «Пуск» и на рабочем столе и запись в **Apps & features** (Приложения и возможности) для удаления.

### Portable.zip

Пользователь распаковывает архив в любую доступную для записи папку и запускает `SinglePass.exe` в её корне:

```
<folder>\
  SinglePass.exe          launcher; start this one
  Update.exe              Velopack updater
  current\                application files; replaced on update
  .portable               marks the copy as portable
```

Обновления применяются на месте, в той же папке. В систему ничего не записывается: ни ярлыков, ни записи для удаления. Чтобы удалить приложение, удалите папку. Папка должна быть доступна пользователю для записи; в `C:\Program Files` без прав администратора обновления не работают.

### Данные пользователя

Хранилище (vault) и настройки **не** входят в установку. Они остаются в `%LocalAppData%\SinglePass` (см. `Constants.LocalAppDataDirectoryPath`) и для Setup, и для Portable. Обновление и удаление их не затрагивают, а портативная копия, перенесённая на другой компьютер, начинает там с пустого хранилища.

Идентификатор пакета Velopack — `SinglePass.WPF` намеренно. Velopack устанавливает в `%LocalAppData%\<packId>` и удаляет эту папку при удалении; идентификатор `SinglePass` поместил бы приложение в папку с данными и удалил бы хранилище при удалении. **Никогда не меняйте идентификатор пакета на `SinglePass`.** Любое его изменение также ломает обновления для существующих установок.

## Как приложение обновляется

1. **Запуск.** `Program.Main` вызывает `VelopackApp.Build().Run()` до старта WPF. Он обрабатывает хуки установки, обновления и удаления (для них процесс завершается) и применяет обновление, скачанное в предыдущем сеансе.
2. **Фоновая проверка.** После первой разблокировки хранилища `UpdateService.Start` ждёт 30 секунд, проверяет наличие обновлений, затем проверяет каждые 12 часов. Учитываются только опубликованные релизы, не являющиеся предварительными (prerelease). Проверки выполняются, только когда включён параметр **Check for updates automatically** (`CheckForUpdates` в `commonSettings.json`, по умолчанию включён).
3. **Загрузка.** Когда есть более новая версия, она скачивается в фоне: по возможности дельта-пакеты от установленной версии, иначе полный пакет. Velopack проверяет каждый пакет по SHA256 из ленты.
4. **Запрос.** Когда загрузка завершена и главное окно открыто, пользователя один раз за сеанс спрашивают, перезапустить ли сейчас. Пока обновление не установлено, рядом с **Settings** в навигации показывается точка, карточка **About** сообщает «Update available: X», а на странице About доступна кнопка **Restart and update**. Работающее приложение никогда не заменяется: SinglePass обычно остаётся в области уведомлений, поэтому обновление ждёт, пока пользователь его перезапустит.
5. **Применение.** При перезапуске приложение штатно завершается (очищая буфер обмена, как обычно), Velopack заменяет `current\` и запускает новую версию. Хранилище нужно разблокировать заново. Если пользователь отказывается, обновление применяется при следующем запуске.

Ручная кнопка **Check for updates** на странице About сразу выполняет шаги 2–4.

Копия, не установленная Velopack (запущенная из Visual Studio или распакованная из старого релиза `SinglePass.WPF.zip`), обновляться сама не может. Страница About сообщает об этом и скрывает элементы управления обновлением.

## Рабочий процесс релиза

Рабочий процесс **Build and create release** запускается вручную на `master`. После восстановления и публикации он:

1. Получает версию из Nerdbank.GitVersioning (`version.json` плюс высота в git), например `1.11.5`, и тег `v1.11.5`. Если этот релиз уже опубликован, остальные шаги пропускаются.
2. Устанавливает CLI Velopack (`vpk`), зафиксированный на той же версии, что и NuGet-пакет `Velopack`.
3. Скачивает полный пакет последнего релиза с помощью `vpk download github`, чтобы следующий шаг мог построить дельту. Если предыдущего релиза на Velopack нет, этот шаг лишь выводит предупреждение.
4. Запускает `vpk pack` для папки публикации с идентификатором пакета `SinglePass.WPF`.
5. Загружает файлы с помощью `vpk upload github` в черновик релиза, генерирует примечания к релизу и публикует релиз.

Релиз становится виден приложению только после шага 5.

При обновлении Velopack меняйте версию пакета `Velopack` в `SinglePass.WPF.csproj` и версию `vpk` в рабочем процессе одновременно.

## Размер дельты

Дельта содержит только двоичную разницу с предыдущей версией. При обычном изменении кода это несколько сотен килобайт, как для однофайловой сборки, так и для сборки с отдельными файлами (измерено локально: около 0,1 МБ против 80 МБ полного пакета). Ожидайте большую дельту при смене патч-версии среды выполнения .NET, поскольку рабочий процесс устанавливает последний SDK `10.0.x`.

## Проверка релиза

1. Запустите рабочий процесс и убедитесь, что релиз содержит перечисленные выше файлы.
2. Установите Setup.exe (или распакуйте Portable.zip). В **About → Updates** **Check for updates** должна сообщить последнюю версию.
3. Отправьте любой коммит в `master` и снова запустите рабочий процесс. Новый релиз должен содержать `-delta.nupkg`.
4. Откройте установленное приложение и разблокируйте его. В течение минуты оно должно предложить перезапуск; либо нажмите **Check for updates**.
5. Согласитесь. Приложение перезапустится, и **About** покажет новую версию.

Чтобы посмотреть индикаторы «обновление готово» в Debug-сборке без релиза, задайте переменную окружения `SINGLEPASS_FAKE_UPDATE` с любой версией (например, `9.9.9`) перед запуском приложения. **Restart and update** в этом режиме ничего не делает.

## Устранение неполадок

- Журнал приложения: `%LocalAppData%\SinglePass\Logs`. `UpdateService` записывает установленную версию, загрузки и ошибки.
- Журнал Velopack: `velopack.log` в папке установки (`%LocalAppData%\SinglePass.WPF` или папка портативной копии).
- GitHub API допускает 60 неаутентифицированных запросов в час с одного IP-адреса. Проверки каждые 12 часов остаются далеко ниже этого предела.

## Ограничения

- Бинарные файлы не подписаны цифровой подписью. Windows SmartScreen предупреждает при первом запуске Setup.exe. Обновления скачивает само приложение, а не браузер, поэтому SmartScreen, как ожидается, не будет запрашивать подтверждение для них (на реальном релизе пока не проверено).
- Хеши пакетов берутся из того же релиза, что и пакеты, поэтому они защищают от повреждённых загрузок, но не от скомпрометированного репозитория или релиза.
- Пользователи релизов до Velopack (`SinglePass.WPF.zip`) должны один раз вручную установить Setup.exe или Portable.zip; их хранилище и настройки подхватываются автоматически.
