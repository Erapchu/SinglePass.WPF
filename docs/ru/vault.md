# Хранилище паролей (Password vault)

Этот документ описывает, как хранилище паролей (vault) хранится, изменяется и синхронизируется. Код находится в `SinglePass.Core`:

- `Services/CryptoService.cs` — формат шифрования файла.
- `Services/CredentialsCryptoService.cs` — хранилище в памяти, локальные изменения, слияние (merge).
- `Services/SyncService.cs` — облачная синхронизация, описана в [cloud-sync.md](cloud-sync.md).
- `Models/PasswordVault.cs` — содержимое хранилища.

Тесты правил слияния и формата хранилища находятся в `SinglePass.Core.Tests`.

## Файл

Хранилище — это один файл, `%LOCALAPPDATA%\SinglePass\singlePass.dat`. Облачная копия имеет то же имя и те же байты: при выгрузке локальный файл отправляется как есть.

<a id="keys"></a>
### Ключи

Содержимое шифруется **ключом хранилища** (vault key): 32 случайных байта, создаются один раз для хранилища (`VaultKey`). Мастер-пароль не шифрует содержимое; он открывает **слот пароля** (password slot) — ключ хранилища, зашифрованный ключом, выведенным из пароля. Поэтому:

- Разблокировка паролем выполняет Argon2 один раз: пароль → слот → ключ хранилища → содержимое. Разблокировка через Windows Hello хранит ключ хранилища и не требует Argon2 (см. README).
- Сохранение шифрует только ключом хранилища, без Argon2. Заголовок, включая слот, остаётся прежним.
- Пока хранилище разблокировано, в памяти находится ключ хранилища, а не пароль. При блокировке он обнуляется. Единственное исключение — первая синхронизация после того, как хранилище было создано или преобразовано в этот сеанс разблокировки, см. [cloud-sync.md](cloud-sync.md#vault-key-and-master-password).
- Смена мастер-пароля создаёт **новый** ключ хранилища и слот и перешифровывает содержимое. Поэтому старый пароль вместе со старой копией файла не открывает файлы, записанные после смены.
- У всех устройств, синхронизирующих хранилище, в итоге один и тот же ключ хранилища: он передаётся внутри облачного файла, в слоте, и никогда в открытом виде (см. [cloud-sync.md](cloud-sync.md#vault-key-and-master-password)).

### Формат шифрования (версия формата 2)

| Смещение | Размер | Содержимое |
|---|---|---|
| 0 | 8 | Сигнатура (magic) `SPVAULT!` |
| 8 | 1 | Версия формата, `2` |
| 9 | 4 | Память Argon2, КиБ (little-endian) |
| 13 | 4 | Число итераций Argon2 (little-endian) |
| 17 | 1 | Параллелизм Argon2 |
| 18 | 16 | Соль Argon2, случайная для каждого слота |
| 34 | 16 | Идентификатор ключа хранилища: первые 16 байт HMAC-SHA256(ключ хранилища, `"SinglePass vault key id"`) |
| 50 | 12 | Слот: nonce AES-GCM |
| 62 | 32 | Слот: ключ хранилища, зашифрованный ключом пароля |
| 94 | 16 | Слот: тег AES-GCM |
| 110 | 12 | Содержимое: nonce AES-GCM, случайный при каждой записи |
| 122 | 16 | Содержимое: тег AES-GCM |
| 138 | остаток | Содержимое: JSON `PasswordVault` в UTF-8, зашифрованный ключом хранилища |

- Ключ пароля: Argon2id v1.3 с параметрами из заголовка (64 МиБ, 3 итерации, параллелизм 4 для новых слотов), 32 байта, из мастер-пароля в UTF-8. При чтении параметры проверяются до запуска Argon2: значения ниже 8 МиБ, 1 итерации или параллелизма 1 делают файл недопустимым; значения выше 1 ГиБ, 32 итераций или параллелизма 16 считаются записанными более новой версией SinglePass. Позже их можно увеличить без новой версии формата, в пределах этих границ; более новая версия, выходящая за них, заставляет старые версии предложить обновление.
- Слот: AES-256-GCM с ключом пароля; байты 0–49 — ассоциированные данные (associated data).
- Содержимое: AES-256-GCM с ключом хранилища; ассоциированные данные — весь заголовок (байты 0–109, включая слот). Любое изменение заголовка или содержимого приводит к ошибке расшифровки.
- Идентификатор ключа позволяет устройству определить, использует ли файл его ключ хранилища, без пароля (синхронизация, резервные копии, Windows Hello). Он ничего не раскрывает о ключе. После открытия слота ключ должен совпадать со своим идентификатором.
- Буферы с ключами и открытым текстом обнуляются после использования.

Байт версии формата описывает только шифрование. Структура JSON внутри имеет собственную `Version` (см. ниже). Файл с версией формата выше 2 считается записанным более новой версией SinglePass (`UnsupportedVaultVersionException`), а не неверным паролем.

### Формат версии 1 (SinglePass 1.x)

| Смещение | Размер | Содержимое |
|---|---|---|
| 0 | 8 | Сигнатура (magic) `SPVAULT!` |
| 8 | 1 | Версия формата, `1` |
| 9 | 16 | Соль Argon2, случайная при каждой записи |
| 25 | 12 | Nonce AES-GCM, случайный при каждой записи |
| 37 | 16 | Тег AES-GCM |
| 53 | остаток | Шифротекст: JSON `PasswordVault` в UTF-8 |

Ключ выводится непосредственно из пароля (Argon2id, 64 МиБ, 3 итерации, параллелизм 4) с новой солью при каждой записи. Файлы формата 1 только читаются: старые резервные копии, облачная история и ещё не обновлённые устройства сохраняют их. Когда локальное хранилище формата 1 разблокируется, оно получает ключ хранилища и перезаписывается в формате 2; старый файл сохраняется как резервная копия `upgrade`. Если файл не удаётся перезаписать (только для чтения, занят другой программой, диск заполнен), хранилище всё равно открывается, а файл остаётся в формате 1 до следующей успешной записи, которая его преобразует; синхронизация записывает его перед выгрузкой. Облачный файл формата 1 преобразуется, когда объединённое локальное хранилище выгружается.

### Устаревший формат (legacy)

Файл, не начинающийся с сигнатуры, читается как старый формат: 16-байтовый IV, за которым следует шифротекст AES-CBC. Ключ — фиксированный 32-байтовый шаблон, в начало которого записаны байты пароля в UTF-8. Устаревшие файлы только читаются и преобразуются так же, как файлы формата 1.

### Запись

Каждая запись идёт во временный файл `singlePass.dat.<guid>.tmp` и сбрасывается на диск (flush). Затем временный файл читается обратно: он должен начинаться ровно с заголовка ключа хранилища в памяти (байт в байт, то есть содержать тот же слот пароля), ключ должен совпадать с идентификатором ключа, а содержимое должно расшифровываться этим ключом. Сам слот пароля проверяется при создании ключа: новый ключ (новое хранилище, преобразование, смена пароля) должен открыться своим паролем до использования, что запускает Argon2 ещё раз; ключ, взятый из облака, происходит из слота, который только что открылся паролем. Только после этого временный файл заменяет `singlePass.dat` через `File.Replace` (или `File.Move` при первой записи). Сбой или неудачная проверка оставляют старый файл нетронутым. Резервные копии описаны [ниже](#backups).

## Содержимое

```jsonc
{
  "Version": 6,
  "Credentials": [ /* Credential */ ],
  "Groups":             { "<group id>":      { "Group": {...} | null, "ModifiedAt": "...", "IsDeleted": false } },
  "Assignments":        { "<credential id>": { "GroupId": "<group id>" | null, "ModifiedAt": "..." } },
  "DeletedCredentials": { "<credential id>": "<deleted at, UTC>" },
  "Trash":              { "<credential id>": { "DeletedAt": "<UTC>" | null, "ModifiedAt": "<UTC>" } },
  "MasterPasswordChangedAt": "<UTC>" | null
}
```

| Версия | Изменение |
|---|---|
| — | Просто JSON-массив учётных записей (до появления групп). Всё ещё читается. |
| 1 | Объект с `Credentials`, `Groups`, `Assignments`. |
| 2 | Добавляет `DeletedCredentials` (надгробия учётных записей, tombstones) и `MasterPasswordChangedAt`. |
| 3 | Добавляет типы записей: `Credential.Type`, по одному блоку данных на тип (`Login`, `SshKey`). Поля логина переносятся из учётной записи в `Login`. |
| 4 | Добавляет платёжные карты: `Credential.Card`. |
| 5 | Добавляет корзину: `Trash`. |
| 6 | Добавляет SSH-хосты: `Credential.Host`. |

- Хранилище с более новой `Version`, чем поддерживает приложение, отклоняется, как локально, так и при синхронизации. Сборки, знающие только версию 1, не могут открыть хранилище версии 2. Это намеренно: старая сборка при следующей записи потеряла бы `DeletedCredentials`, и удалённые учётные записи вернулись бы. По той же причине сборки, знающие только версию 2, не могут открыть хранилище версии 3: они не нашли бы поля логина, перенесённые в `Login`, и потеряли бы данные SSH-ключей. Сборки, знающие только версию 3, не могут открыть хранилище версии 4: они потеряли бы данные карт. Сборки, знающие только версию 4, не могут открыть хранилище версии 5: они показывали бы записи из корзины как обычные и потеряли бы состояние корзины. Сборки, знающие только версию 5, не могут открыть хранилище версии 6: они потеряли бы данные хостов.
- Такое хранилище сообщается как записанное более новой версией SinglePass (`UnsupportedVaultVersionException`): окно разблокировки и синхронизация предлагают обновить SinglePass вместо запроса другого пароля. SinglePass 1.x не отличает эти два случая и продолжает запрашивать пароль для более новой облачной копии; саму копию он не изменяет.
- Старые хранилища обновляются в памяти и записываются в текущей версии при следующем изменении. Для версий до 3 поля `LoginField`, `PasswordField`, `SiteField`, `Totp` и `PasswordHistory` каждой учётной записи переносятся в объект `Login` до чтения JSON. Это происходит в `ReadVault`, поэтому локальное хранилище, резервные копии и облачная копия преобразуются одинаково.
- Отсутствующая коллекция читается как пустая; явный `null` делает файл недопустимым.

### Учётная запись (Credential)

Учётная запись содержит поля, общие для всех записей, свой тип и один блок данных для этого типа:

```jsonc
{
  "Id": "<guid>",
  "Type": 0,                         // 0 login (also when missing), 1 SSH key, 2 card, 3 host
  "NameField": {...}, "OtherField": {...}, "AdditionalFields": [...],
  "CreationTime": "...", "LastModifiedTime": "...",
  "Login":  { "LoginField": {...}, "PasswordField": {...}, "SiteField": {...}, "Totp": {...} | null, "PasswordHistory": [...] } | null,
  "SshKey": { "PrivateKey": "...", "PublicKey": "...", "Passphrase": "..." } | null,
  "Card":   { "Number": "...", "Holder": "...", "Expiry": "MM/YY", "Cvv": "...", "Pin": "...", "Brand": 2 | null } | null,
  "Host":   { "Hostname": "...", "Port": 2222 | null, "Username": "...", "SshKeyId": "<guid>" | null } | null
}
```

- `Id` — GUID, идентичность записи. Равенство сравнивает только `Id`.
- `Type` — выбирается при создании записи (меню **New item**) и никогда не меняется; редактирование записи в другой тип отклоняется.
- Задан только блок, соответствующий типу записи; остальные равны null. `Credential.EnsureTypeData` обеспечивает это при чтении хранилища и при добавлении или редактировании записи, так что правило не зависит от UI.
- `Login.PasswordHistory` — до 10 предыдущих паролей, самые новые первыми. Когда сохранение меняет непустой пароль, старый добавляется с текущим временем UTC.
- `SshKey.PrivateKey` — текст файла ключа (OpenSSH или PEM, возможно зашифрованный `Passphrase`); `PublicKey` — строка `authorized_keys`.
- `Card.Brand` — платёжная система, выбранная пользователем (`CardBrand`, число); null означает, что она определяется по номеру при показе. Редактор принимает только цифры в номере, `MM/YY` в сроке действия и цифры в CVV и PIN (`CardNumbers`, `CardInput`); значения, сохранённые до этих правил, остаются как есть до редактирования. Номер, не прошедший проверку Луна (Luhn), всё равно сохраняется, с предупреждением в редакторе.
- `Host.Port` равный null означает 22. `Host.SshKeyId` — это `Id` записи SSH-ключа, с которым выполняется вход. Это обычная ссылка: удаление ключа или перенос его в корзину не изменяет хост, который затем показывает ключ как отсутствующий. Закрытый ключ используется через SSH-агент, см. [ssh-agent.md](ssh-agent.md).
- `LastModifiedTime`, `CreationTime` — UTC, устанавливаются UI при сохранении. Старые хранилища хранили местное время со смещением; модель преобразует любое значение в UTC при присвоении, а UI показывает местное время.

Слияние, надгробия, группы и резервные копии не зависят от типа: запись выигрывает или проигрывает целиком. Истории паролей объединяются только для логинов.

#### Добавление типа записи

1. Значение в `CredentialType` и класс данных (например, `CardData`) с методом `Clone`.
2. Свойство в `Credential`, строка в `EnsureTypeData` и в `Clone`.
3. Новая `Version` хранилища, чтобы старые сборки отказывались от хранилища, а не теряли новый блок.
4. UI, в `SinglePass.WPF`:
   - модель представления в `ViewModels/Entries`, производная от `CredentialDataViewModel` (подзаголовок списка, глиф, тексты для поиска) и вариант в `CredentialViewModel.CreateData`;
   - представление и редактор в `Views/Controls/Entries`, зарегистрированные как `DataTemplate` для модели представления в `CredentialsDetailsControl.xaml`;
   - пункт в меню **New item** (`PasswordsControl.xaml`), категория в боковой панели (`MainWindowViewModel.CategoryNavigation`) и строки.

   Боковая панель выбирает один фильтр за раз: все записи, категорию (тип записи) или группу. В категории кнопка добавления сразу создаёт запись этого типа; в остальных случаях она спрашивает тип.

   Сама карточка, список, поиск, группы и процесс сохранения не требуют изменений: они показывают название, заметки, дополнительные поля и даты, а остальное берут из модели представления типа.

## Локальные операции

Все операции берут внутрипроцессную блокировку по пути хранилища, применяют неизменяемое (immutable) изменение к хранилищу, записывают файл и только потом заменяют хранилище в памяти. Если запись не удалась, память остаётся без изменений. Заблокированное хранилище отклоняет все изменения.

| Операция | Эффект |
|---|---|
| Add credential | Добавляет в конец, при необходимости назначает группу. Удаляет надгробие с тем же `Id`, если оно есть. |
| Edit credential | Заменяет запись, обновляет историю паролей, при необходимости переназначает группу. |
| Move to trash | Устанавливает `Trash[id] = { DeletedAt: UtcNow, ModifiedAt: UtcNow }`. Учётная запись и её связь с группой остаются. |
| Restore from trash | Устанавливает `Trash[id] = { DeletedAt: null, ModifiedAt: UtcNow }`. |
| Delete credential | Удаляет запись, её назначение группе и состояние корзины, добавляет надгробие `DeletedCredentials[id] = UtcNow`. Используется для удаления из корзины, очистки корзины и для просроченных записей. |
| Save group | Сохраняет группу с `ModifiedAt = UtcNow`. Редактирование удалённой группы ничего не делает. |
| Delete group | Заменяет группу надгробием (`Group = null`, `IsDeleted = true`). Назначения ей остаются, но игнорируются. |
| Move credentials | Устанавливает назначение для каждой существующей записи, `ModifiedAt = UtcNow`. |
| Change master password | Проверяет текущий пароль по слоту пароля, создаёт резервную копию `password`, устанавливает `MasterPasswordChangedAt = UtcNow` и перезаписывает хранилище с новым ключом хранилища и слотом для нового пароля. |
| Lock | Помечает хранилище заблокированным, очищает его и обнуляет ключ хранилища в памяти, отменяет облачные передачи. |

Назначения групп, указывающие на отсутствующую или удалённую группу, считаются «без группы».

### Корзина (Trash)

Удаление записи в UI переносит её в корзину (**Deleted** в боковой панели, `TrashViewModel`). Запись в корзине сохраняет все свои данные и группу, но не показывается в списке, категориях, группах, поиске и всплывающем окне: `CredentialsCryptoService.Credentials` её не включает, `TrashedCredentials` перечисляет. Из корзины запись можно восстановить (одну или все) или удалить навсегда (одну или через **Empty trash**).

Записи удаляются навсегда через `PasswordVault.TrashRetention` (30 дней) после переноса в корзину. Это происходит при разблокировке хранилища и при открытии страницы **Deleted**, как обычное удаление с надгробием, поэтому распространяется при синхронизации.

Восстановление сохраняет запись корзины с `DeletedAt = null`, а не удаляет её, поэтому при синхронизации выигрывает более позднее из событий: перенос в корзину или восстановление.

## Слияние (Merge)

`CredentialsCryptoService.MergeVaults(local, incoming, result)` — чистая функция. Она возвращает `local` без изменений, если ничего записывать не нужно. Шаги по порядку:

1. **Надгробия.** Объединение обоих `DeletedCredentials`; для одного и того же id выигрывает более позднее время.
2. **Учётные записи.** Неизвестный `Id` добавляется. Для известного версия с более поздним `LastModifiedTime` выигрывает целиком (без слияния по полям). Истории паролей обеих версий объединяются, дедуплицируются и обрезаются до 10.
3. **Применение надгробий.** Учётная запись с надгробием удаляется, если только её `LastModifiedTime` (преобразованное в UTC) не позже удаления. В этом случае выигрывает правка: запись остаётся, а надгробие отбрасывается.
4. **Группы.** Неизвестная группа добавляется. Удалённая группа остаётся удалённой. В остальных случаях выигрывает удаление, затем более поздний `ModifiedAt`.
5. **Назначения.** Сохраняются только для записей, существующих после шага 3. Для одной и той же записи выигрывает более поздний `ModifiedAt`.
6. **Корзина.** Сохраняется только для записей, существующих после шага 3. Для одной и той же записи выигрывает более поздний `ModifiedAt`. Записи, оказавшиеся в корзине, не сообщаются как новые или изменённые.
7. **Время мастер-пароля.** Сохраняется более позднее `MasterPasswordChangedAt`.

Результат перечисляет новые, изменённые (победившая версия) и удалённые учётные записи, а также изменились ли группы; UI показывает его после синхронизации. Изменения, затрагивающие только надгробия или очистку назначений, записываются, но не сообщаются.

Надгробия учётных записей и групп никогда не удаляются.

## Резервные копии (Backups)

`Services/VaultBackups.cs` копирует зашифрованный файл хранилища в `%LOCALAPPDATA%\SinglePass\Backups\singlePass-<UTC yyyyMMdd-HHmmss-fff>-<reason>.dat`. Резервная копия — это файл в точности как он был, поэтому она открывается мастер-паролем того момента, а без пароля — пока использует текущий ключ хранилища. Хранятся 20 новейших; более старые удаляются при создании новой.

| Причина | Когда |
|---|---|
| `daily` | Перед локальным изменением, если новейшей копии любого вида не менее суток. Сбой записывается в журнал, а изменение всё равно сохраняется. |
| `sync` | Перед тем, как синхронизация записывает изменения, пришедшие из облака. |
| `password` | Перед сменой мастер-пароля или заменой его облачным при синхронизации. |
| `restore` | Перед восстановлением из резервной копии. |
| `upgrade` | Перед перезаписью файла хранилища SinglePass 1.x в формате 2. Один раз на файл: если новейшая копия `upgrade` содержит те же байты (предыдущее преобразование не смогло записать), новая не создаётся. Сбой записывается в журнал, и преобразование продолжается. |

Кроме `daily` и `upgrade`, неудачная резервная копия отменяет операцию.

### Восстановление (Restore)

**Settings → Security → Backups** перечисляет резервные копии. Восстановление одной из них (`CredentialsCryptoService.ApplyBackup`) применяет её поверх текущего хранилища как новое изменение и ничего не удаляет:

- записи, отсутствующие сейчас, возвращаются; отличающиеся записи возвращаются к версии из копии, а текущий пароль попадает в историю паролей;
- записи, созданные после копии, остаются;
- группы и связи с группами записей из копии возвращаются к состоянию копии; группа, удалённая после копии, возвращается под новым id, потому что надгробие группы при синхронизации всегда выигрывает;
- записи, находящиеся сейчас в корзине, но не бывшие в корзине в копии, восстанавливаются из неё; записи, бывшие в корзине в копии, не восстанавливаются;
- каждому восстановленному элементу ставится текущее время, поэтому следующая синхронизация распространяет восстановление в облачную копию и на другие устройства, а не отменяет его (восстановленная запись новее надгробия, удалившего её).

Резервная копия, использующая текущий ключ хранилища, открывается без пароля; сделанная до смены пароля (другой ключ) или SinglePass 1.x запрашивает пароль этой копии. Восстановление копированием файла поверх `singlePass.dat` тоже работает, но тогда следующая синхронизация снова подмешает более новые облачные изменения и удаления.

## Известные ограничения

- **Разрешение конфликтов по часам.** Конфликты учётных записей, правка против удаления и смены мастер-пароля решаются по меткам времени с часов устройства. Расхождение часов выбирает неверного победителя. Одновременные правки разных полей одной учётной записи не объединяются.
- **Резервные копии локальны.** Они лежат рядом с хранилищем только на этом устройстве; потеря устройства означает потерю копий.

Ограничения, специфичные для синхронизации, перечислены в [cloud-sync.md](cloud-sync.md#known-limitations).
