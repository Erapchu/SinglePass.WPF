# SSH-агент

SinglePass отдаёт записи с SSH-ключами из хранилища (vault) программам `ssh`, `git`, `scp` и другим клиентам OpenSSH — так же, как `ssh-agent`, 1Password или Bitwarden. Программы получают подписи, но никогда не получают сами ключи.

Код:

- `SinglePass.Core/Services/SshAgent.cs` — протокол агента (draft-miller-ssh-agent): список ключей, подпись.
- `SinglePass.Core/Services/SshAgentServer.cs` — канал (pipe) агента; сам канал (ACL, первый экземпляр, программа, которая подключается) реализован в `NamedPipeServer.cs`, общем с каналом расширения браузера.
- `SinglePass.Core/Services/SshSigningKey.cs` — читает закрытые ключи и подписывает: Ed25519, RSA (`ssh-rsa`, `rsa-sha2-256`, `rsa-sha2-512`), ECDSA на NIST P-256/384/521.
- `SinglePass.Core/Services/BcryptPbkdf.cs` — функция выработки ключа для ключей OpenSSH с парольной фразой.
- `SinglePass.WPF/Services/SshAgentKeyStore.cs` — ключи разблокированного хранилища, подтверждение, разблокировка по запросу.

Тесты находятся в `SinglePass.Core.Tests/SshAgentTests.cs`, с ключами, созданными `ssh-keygen`.

## Канал (Pipe)

`\\.\pipe\singlepass-ssh-agent-<user SID>`. У него собственное имя, поэтому он не конфликтует со службой Windows `ssh-agent` (`\\.\pipe\openssh-ssh-agent`), а SID разделяет пользователей одной машины: имена каналов общие для всех сеансов.

- ACL канала разрешает доступ текущему пользователю и запрещает сетевые входы. Подключаться могут только процессы этого пользователя на этой машине.
- Первый экземпляр создаётся с `FirstPipeInstance`. Если это имя уже занято другой программой, агент не запускается (и пишет об этом в журнал), а не делит имя с ней.
- Агент запускается после первой разблокировки и работает, пока SinglePass не завершится. **Settings → Security → SSH agent** выключает его и показывает адрес.

Клиенты находят его одним из двух способов:

| Где | Значение |
|---|---|
| Переменная окружения `SSH_AUTH_SOCK` (все программы) | `\\.\pipe\singlepass-ssh-agent-<SID>` |
| Параметр `IdentityAgent` у `ssh` / `ssh_config` | `//./pipe/singlepass-ssh-agent-<SID>` |

`IdentityAgent` требует прямых слэшей: разборщик параметров ssh воспринимает обратные слэши как экранирование. Windows принимает обе формы.

С именованными каналами работает только OpenSSH для Windows (`C:\Windows\System32\OpenSSH`). `ssh` из Git for Windows (MSYS) ожидает Unix-сокет и не может использовать агент.

## Запросы

| Запрос | Ответ |
|---|---|
| Список ключей (11) | Записи SSH-ключей хранилища (не в корзине), чей открытый ключ удаётся прочитать, с именем записи в качестве комментария. Ничего, пока хранилище заблокировано. |
| Подпись (13) | Спрашивает пользователя, затем подписывает ключом. Отказ, если ключ неизвестен, запрещён или не может быть прочитан. |
| Всё остальное | Отказ. Ключи нельзя добавлять или удалять через агент, а расширения вроде `session-bind@openssh.com` не поддерживаются (клиенты продолжают работу без них). |

Открытый ключ записи берётся из её закрытого ключа, если тот можно прочитать без парольной фразы (ключи OpenSSH — всегда, незашифрованные PEM-ключи), иначе — из поля открытого ключа записи. Перед подписью расшифрованный ключ сверяется с запрошенным открытым ключом.

## Заблокированное хранилище

Запрос при заблокированном хранилище показывает окно разблокировки (не чаще раза в 30 секунд) и ждёт разблокировки до минуты. Затем запрос продолжается как обычно или получает пустой список ключей.

## Подтверждение

Каждая подпись подтверждается в окне поверх остальных. Оно показывает ключ и программу, вместе с программами, которые её запустили, например `ssh.exe ← git.exe ← Code.exe`, и путь первой из них.

- Enter и Escape отклоняют запрос, поэтому нажатие клавиши, предназначенное другому окну, не может разрешить запрос. Без ответа запрос отклоняется через минуту.
- **Allow this program until the vault is locked** запоминает ключ вместе со всей цепочкой программ (пути). Одобрения заканчиваются при блокировке хранилища.
- Один вопрос за раз; запросы ждут своей очереди.

## Хосты

Запись хоста (`HostData`) хранит адрес, порт, пользователя и ссылку на запись SSH-ключа. Аргументы ssh строит `SinglePass.WPF/Helpers/SshCommands.cs`:

```
-o IdentityAgent=//./pipe/singlepass-ssh-agent-<SID> -o IdentitiesOnly=yes -i "%LOCALAPPDATA%\SinglePass\ssh\<key id>.pub" -p <port> -- user@host
```

Открытый ключ записывается в `%LOCALAPPDATA%\SinglePass\ssh\<key id>.pub` (открытые ключи не секретны). Когда `-i` указывает на него и задано `IdentitiesOnly=yes`, ssh предлагает только этот ключ и просит агент подписать им. Без связанного ключа или при выключенном агенте остаётся только `-p <port> -- user@host`. `-p` опускается для порта 22. `--` не даёт хосту или пользователю, начинающемуся с `-` (например, `-oProxyCommand=…` из синхронизированного хранилища), быть прочитанным как параметр.

- **Connect** запускает `C:\Windows\System32\OpenSSH\ssh.exe` с этими аргументами в новой вкладке окна Windows Terminal с именем `SinglePass` (`wt -w SinglePass new-tab --title <entry name> …`), так что все подключения используют одно окно. `;` в аргументах экранируется как `\;`, потому что `wt` разбивает команды по нему. Без Windows Terminal ssh открывается в собственном окне консоли. Используется полный путь, потому что `ssh` из Git for Windows, который может стоять первым в `PATH`, не умеет работать с агентом.
- **Copy SSH command** копирует `ssh` с теми же аргументами, чтобы вставить в любой терминал.

## Ограничения

- Пока хранилище разблокировано, программа, запущенная от того же пользователя, может прочитать память SinglePass. Подтверждение защищает от скрытого использования через агент, но не от этого.
- `ForwardAgent` позволяет удалённому серверу использовать агент, пока длится сеанс. Его запросы приходят через локальный `ssh.exe`, поэтому запомненное одобрение для этого ssh распространяется и на них. Не пробрасывайте агент на серверы, которым не доверяете.
- Ключи на аппаратных устройствах (`sk-ssh-ed25519`, `sk-ecdsa`) и ключи DSA не поддерживаются.
